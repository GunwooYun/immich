## Answers to the four things you asked me to attack

### 1. The K1 guard — right precedence, both failure modes, no leak

`if ! { { echo …; printf …; } > "$SC_TMP" && mv "$SC_TMP" "$SC_BASELINE"; }; then` is correct:
`!` negates the whole brace group, so any non-zero status inside it — the redirect failing, the
`printf` failing, or the `mv` failing — reaches the error branch.

**Both modes verified, including the one you listed as unverified:**

```
mv failure (unwritable dir):
  mv: cannot move '/tmp/tmp.T4GK9uKYYB' … Permission denied
  -> install FAILED loudly (exit 1); temp left? no
  dest still: OLD                                   ← old baseline untouched

write failure (group redirected to /dev/full — real ENOSPC):
  bash: echo: write error: No space left on device
  bash: printf: write error: No space left on device
  -> caught the write failure ✓
```

So the disk-full branch is no longer a caveat: the shell does surface write errors on a redirected
builtin, the group's status goes non-zero, `&&` short-circuits, and `mv` never runs.

**No temp leak on any path.** If the redirect fails, `mktemp` has already created the file and
`rm -f` removes it; if `mv` fails, same; if `mv` succeeds the file is gone by definition. The only
gap is `mktemp` itself failing, which leaves `SC_TMP` empty and makes `rm -f ""` a harmless no-op —
not worth guarding.

Worth noting the improvement over last round in kind, not just in outcome: the previous form
computed a status and discarded it, so the failure existed but was invisible. Now the status *is*
the control flow. That is the shape that stops this recurring.

### 2. The K2 header — inert in every direction, and the zero-error state is now strict

`NR==FNR { if ($0 ~ /^#/) next; base[$1]=$2; next }` skips the header on the **baseline** read only,
which is the right placement: `SC_CUR` is generated by `sc_extract`, whose keys are svelte-check
paths, and a source path cannot begin with `#`. So there is no need for the same guard on the
current side and no phantom key from either.

All three directions checked against a header-only baseline (the zero-error state):

```
header-only + a new error  -> REGRESSION src/NEW.svelte      (fails closed ✓)
header-only + clean tree   -> (nothing)                      (no STALE nag ✓)
-s passes on it            -> yes                            (representable ✓)
```

That is exactly the property K2 was after, and it makes the gate *stricter* in that state rather
than weaker: with no tolerated files, any error anywhere is a regression. Dropping the zero-error
refusal was the right call — it was the half of the dead end that had no escape.

The header text doubles as a self-documenting pointer back to the regen command, which is a nice
touch for a file that must never be hand-edited.

### 3. The re-indent — whitespace-only, and behaviour re-verified

`git show bde9baba5 -w` (ignoring whitespace) leaves only the K1/K2 logic and some comment
rewrapping. So structurally it is what you claim.

I did not stop there, because `-w` cannot prove the nesting still routes failures correctly. All
three outcomes re-driven through the re-indented block:

```
real regression -> "svelte-check regressions vs baseline:"
                     …/+page.svelte   4   0                    -> RESULT: FAIL
inflated baseline -> "…baseline is stale…" + per-file lines     -> RESULT: PASS   (still non-fatal)
clean tree        -> "no svelte-check regressions vs baseline (3 pre-existing files)" -> RESULT: PASS
```

`bash -n` passes and the `if/else/fi` is balanced — and now that the indentation matches the
nesting, the `# close:` label comments are correctly gone. Their removal is the real evidence the

## L1 — the zero-error baseline carries a blank line, and the file count is off by one

`printf '%s\n' "$NEW"` emits one newline even when `NEW` is empty, so the zero-error baseline is:

```
# svelte-check baseline — regenerate with: ./dev-test/google-drive/run.sh --regen-baseline
                                            ← a blank line
```

The blank line is **harmless to the comparison** — I checked, and it behaves identically to the
header-only file (new error → REGRESSION, clean → no STALE). The problem is the count, which is
`grep -vc '^#'` in two places:

```
$ grep -vc '^#' <zero-error baseline>
1                                    ← should be 0
```

so in that state regen prints *"baseline regenerated (1 files)"* and, more durably, the gate prints
*"no svelte-check regressions vs baseline (**1** pre-existing files)"* on every run from then on.
A small lie, but a permanent one, in the state this round exists to support.

**And the obvious fix is a trap** — worth spelling out, because `set -e` is deliberately not on
here and the failure would look like K1 regressing:

```bash
# WRONG: when NEW is empty the test fails, so the *group* exits 1, `&&` short-circuits,
#        and the K1 guard reports a false install failure.
{ echo "# …"; [[ -n "$NEW" ]] && printf '%s\n' "$NEW"; } > "$SC_TMP" && mv …

# RIGHT: the || form always exits 0.
{ echo "# …"; [[ -z "$NEW" ]] || printf '%s\n' "$NEW"; } > "$SC_TMP" && mv …
```

Verified both:

```
naive [[ -n ]] && printf  -> FALSE install failure
[[ -z ]] || printf        -> installs correctly, lines=1 (header only)
```

Pair it with a count that counts data rows rather than non-comments — the rows are the ones with a
tab:

```bash
$(grep -c $'\t' "$SC_BASELINE")
```

That reads 0 for a header-only file and 3 today, and it stays right if a future header gains more
comment lines.
